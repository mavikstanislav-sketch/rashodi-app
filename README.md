# Учёт личных расходов

Веб-приложение для учёта личных расходов по категориям с привязкой к карте.
Личный кабинет показывает, сколько потрачено за месяц, по каждой категории,
и сколько осталось от месячного бюджета.

Архитектура, модель данных (ER-схема) и спецификация маршрутов — в [ARCHITECTURE.md](ARCHITECTURE.md).
Как открыть приложение и с компьютера, и с телефона (разместить в интернете) — в [DEPLOY.md](DEPLOY.md).

## Технологический стек

Выбран самостоятельно (в задаче стек не был задан):

- **Node.js + Express** — сервер и роутинг.
- **`@libsql/client`** — SQLite-совместимая БД. Локально пишет в файл (`data/rashodi.db`),
  без нативной сборки (Python/node-gyp не нужны). В продакшене тем же клиентом
  подключается к бесплатной облачной БД **Turso** — это даёт постоянное хранилище
  на хостингах без диска (см. [DEPLOY.md](DEPLOY.md)).
- **EJS** — серверный рендеринг страниц личного кабинета.
- **express-session + bcryptjs** — аутентификация по email/паролю с хэшированием пароля.
- **PWA** (manifest + service worker) — приложение можно установить на главный экран
  телефона и в браузере на ПК, чтобы оно открывалось как отдельное приложение.
- Без фреймворков на фронте, без Docker — чтобы демо запускалось одной командой.

## Ответы на открытые вопросы (решения по умолчанию для демо)

| Вопрос | Решение |
|---|---|
| Откуда берётся остаток | Пользователь сам задаёт месячный бюджет (лимит) в личном кабинете. Остаток = бюджет − потрачено. Интеграции с банком нет. |
| Тип приложения | Веб-приложение (Express + EJS), открывается в браузере. |
| Многопользовательность | Да, есть регистрация и вход по email/паролю (каждый пользователь видит только свои данные). |
| Свои категории | Нет, сознательно ограничено 3 заданными категориями — как указано в задаче. |
| Несколько карт на пользователя | Да, можно добавить несколько карт и выбирать карту при добавлении расхода. |
| Хранение номера карты | Хранятся **только последние 4 цифры**, полный номер никогда не сохраняется и не логируется. |
| История за прошлые месяцы | Да, есть переключатель месяца и отчёты по каждому прошлому месяцу. |
| База данных / развёртывание | Локально — файл SQLite (`data/rashodi.db`), Docker не требуется. В интернете (по запросу) — бесплатная облачная БД Turso + хостинг, см. [DEPLOY.md](DEPLOY.md). |
| Доступ с ПК и телефона | Веб-приложение с адаптивной вёрсткой и PWA-манифестом: открывается в браузере на любом устройстве, можно «установить» на главный экран/рабочий стол. |

## Что реализовано (по критериям готовности)

- 3 предзаданные категории: «Заправка», «Заведения», «Магазины продуктовые».
- Полный CRUD расходов: добавление, редактирование и удаление (сумма, категория, дата, карта, заметка).
- Привязка расходов к карте (несколько карт на пользователя, храним только last4).
- Подсчёт за месяц: итог, разбивка по категориям, остаток бюджета, % использования.
- Личный кабинет: регистрация/вход, экран с текущими суммами, остатком и историей трат.

## Собственные дополнения (по своему усмотрению)

1. **Визуализация расходов** — донат-диаграмма и цветовой индикатор прогресса
   (зелёный / жёлтый / красный в зависимости от % использования бюджета), чтобы
   сразу было видно, насколько близко пользователь подошёл к лимиту.
2. **История по месяцам** — переключатель месяца позволяет посмотреть расходы,
   итоги и разбивку по категориям за любой предыдущий месяц, а не только за текущий.

## Демо-доступ

Приложение при первом запуске автоматически создаёт демо-пользователя с
тестовыми картами и расходами за текущий и прошлый месяц:

```
Email:  demo@example.com
Пароль: demo1234
```

Так можно сразу посмотреть, как всё работает, не вводя реальные данные карты.
Когда захотите использовать свои данные — просто зарегистрируйте новый аккаунт
(«Зарегистрироваться» на странице входа) и добавьте свою карту и расходы.

## Запуск

```bash
npm install
npm start
```

Приложение поднимется на `http://localhost:3000` (порт можно поменять через `PORT`
в `.env`, см. `.env.example`).

## Структура проекта

```
src/
  db/          — подключение к БД (файл локально / Turso в продакшене), схема, сид демо-данных
  middleware/  — проверка авторизации
  utils/       — asyncHandler (проброс ошибок async-роутов в error-middleware)
  models.js    — запросы к БД и расчёт месячной статистики
  routes/      — auth (вход/регистрация) и dashboard (личный кабинет, расходы, карты)
  views/       — EJS-шаблоны (login, register, dashboard, edit-expense)
public/
  css/         — стили
  icons/       — иконки PWA
  manifest.json, sw.js — установка приложения на устройство
data/          — файл SQLite для локальной разработки (создаётся автоматически, не коммитится)
```

## Безопасность

- Пароли хранятся только в виде bcrypt-хэша.
- Номер карты никогда не сохраняется полностью — только последние 4 цифры для отображения.
- Сессии — через `express-session` с httpOnly cookie.

Для продакшена (не входит в объём демо): HTTPS, ротация `SESSION_SECRET`,
ограничение частоты попыток входа, полноценная миграция схемы БД.
